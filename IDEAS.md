## AI workspace/project continuity as an optional first-use accelerator

Evaluate platform-native project/workspace context (for example ChatGPT Projects) as an optional accelerator, not as U-GAS authority or a required route. Current ChatGPT Projects can keep related chats, files, project instructions, saved responses, and supported app sources together; Plus/Pro project chats can prioritize project chats/files. On desktop, a Project can also start a Work thread using project context, while Codex remains a separate workflow/history surface. Project-only memory has an important current limitation: ChatGPT Work is not available in projects using project-only memory.

Potential simplification: when a user already works inside a capable AI project/workspace, let that layer carry conversational context and let U-GAS focus on durable/verifiable repository state. This may reduce repeated first-contact explanation and some clipboard coordination without making U-GAS ChatGPT-specific.

Do not add a new Starter route yet. First audit the existing generated prompt and post-Copy flow for text that becomes redundant when the coordinating AI already has project/workspace context. Any adaptation must remain tool-neutral, preserve repo/PICA authority, work without platform memory, and never imply that platform memory is deterministic durable project state.
